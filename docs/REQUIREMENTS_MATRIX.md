# ZURUV — REQUIREMENTS MATRIX

**Roles:** CUS = Customer · OWN = Venue Owner · ADM = Admin · ALL = all roles.
**Priority:** Critical = required for a bookable, payable platform · High = required for launch · Medium = launch scope but can follow core flows · Low = optional or dependent on approval.
**Basis:** *Confirmed* = stated in the brief and/or shown on the UI boards. *Confirmed; rule pending Qn* = the feature is confirmed but a business rule is not. *Proposed* = my recommendation, not supported by the references. *Pending decision* = may be removed or changed by a client answer. Proposed items are never treated as scope until approved.
**Source:** `Brief §n`; `C-Sn` = Customer board screen n; `O-Sn` = Owner board screen n. The quotation PDF and walkthrough video were **not available**; no row is verified against them `[verify vs quotation/video]`.
**Pending decisions** (`Qn`, `Cn`, `Nn`) refer to `OPEN_QUESTIONS.md`. A row that depends on an open decision is not implementable until it is answered.
DB names below are working names, finalised in Stage 3.
